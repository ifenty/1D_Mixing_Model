# GGL90 validation NetCDF format

Mirrors `KPP_port_validation/NETCDF_DATA_FORMAT.md`'s split-file convention.
Generated by `scripts/parse_mitgcm_ggl90_split.py` from
`mitgcm_verification_mods/ggl90_mods/ggl90_calc.F`'s instrumented STDOUT.

## Key difference from KPP: GGL90 is prognostic

KPP is diagnostic (single-call, no persistent state). GGL90 evolves TKE as a
state variable, so the captured input includes **`tke_before`** (TKE(t), the
value on entry to this call, before it gets mutated in place) alongside the
usual state/forcing, and the output includes **`tke_after`** (TKE(t+1), the
value after the call's implicit tridiagonal solve). This supports
single-step-replay validation: feed the Python port `tke_before` directly
(not its own previously-computed TKE) and compare its one-step output
against `tke_after`, isolating formula agreement from trajectory drift.

## Inputs (`mitgcm_ggl90_inputs*.nc`)

| Variable | Dims | Units | Notes |
|---|---|---|---|
| `temperature`, `salinity`, `u_velocity`, `v_velocity` | (time,x,y,z) | degC, psu, m/s | cell-centered state at t |
| `tke_before` | (time,x,y,z) | m^2/s^2 | GGL90TKE captured on entry, before mutation |
| `tau_x`, `tau_y` | (time,x,y) | m^2/s^2 | wind stress / rho (raw forcing) |
| `u_star_sq` | (time,x,y) | m^2/s^2 | MITgcm's post-sqrt `uStarSquare` = sqrt(tau_x^2+tau_y^2); matches Python `compute_mixing`'s `u_star_sq` arg directly |
| `depth`, `cell_thickness` | (z,) | m | rC, drF |

Global attrs: `PARAM_*` -> `GGL90ck`, `GGL90ceps`, `GGL90alpha`, `GGL90m2`,
`GGL90TKEmin`, `GGL90TKEsurfMin`, `GGL90TKEbottom`, `GGL90mixingLengthMin`,
`GGL90viscMax`, `GGL90diffMax`, `mxlMaxFlag`, `GGL90_dirichlet`,
`calcMeanVertShear`, `gravity`, `rhoConst`, `viscAz` (background), `diffKzS`
(background).

## Outputs (`mitgcm_ggl90_outputs*.nc`)

| Variable | Dims | Units | Notes |
|---|---|---|---|
| `visc_az` | (time,x,y,z) | m^2/s | `GGL90visctmp`: cell-centered KappaM, pre-U/V-stagger |
| `diff_kz` | (time,x,y,z) | m^2/s | `GGL90diffKr` |
| `mixing_length` | (time,x,y,z) | m | `GGL90mixingLength` |
| `tke_after` | (time,x,y,z) | m^2/s^2 | `GGL90TKE` after the implicit solve |

## Generating a capture

Experiment: `vermix` (MITgcm's own purpose-built single-column vertical-mixing
verification experiment; `1D_ocean_ice_column` doesn't include GGL90 in its
package list). Requires merging `vermix/input/` (base: grid, T/S init,
forcing files) with `vermix/input.ggl90/` (override: `data.pkg` switches
`useGGL90=.TRUE.`, plus `data.ggl90`/`data.diagnostics`) -- see
`mitgcm_verification_mods/ggl90_mods/README` (TODO) or replicate via:

```
mkdir vermix/input_ggl90_merged
cp vermix/input/* vermix/input_ggl90_merged/
cp vermix/input.ggl90/* vermix/input_ggl90_merged/   # overrides data.pkg etc.
./experiment_compile.sh vermix -mods <repo>/mitgcm_verification_mods/vermix/code_validation -build build_docker_ggl90
./experiment_run_no_compile.sh vermix input_ggl90_merged -build build_docker_ggl90 -output output_ggl90
python3 scripts/parse_mitgcm_ggl90_split.py vermix/output_ggl90/output.txt vermix_ggl90
python3 scripts/run_ggl90_from_netcdf_input.py vermix/output_ggl90/mitgcm_ggl90_inputs.nc -o <out>.nc
```

## Known blocking finding (as of first capture, 2026-09-16)

See open issue **1DMIX-014**: the Python port's mixing-length limiter
(`GGL90MixingLength.compute()`) applies `GGL90mixingLengthMin` as an
unconditional floor to every level, but MITgcm's own two-way-sweep algorithm
(`mxlMaxFlag` 2/3) only uses that parameter as a boundary seed/cap term, not
a blanket floor -- causing large, systematic mixing-length (and downstream
viscosity/diffusivity/TKE) mismatches. Do not treat comparisons run before
that is fixed as validation evidence.
